# ADR-0023: A smarter, broader loop - switches, patch edits, affected tests, verification, Go, safe memory (Phase 16)

**Status:** accepted (built, **nothing measured on a real model**). **Principle:** a feature that has not been measured does not
change production behaviour. Every Phase 16 behaviour is a `LoopConfig` switch that is **off** in E3 and has its own ablation preset.

## Why this phase is smaller than the roadmap

Phase 16 was meant to be *guided by the Phase 14 real-model results* ("fix the biggest failure classes", "languages where
Phase 14 shows demand"). Those results do not exist: every number in the repository still comes from the synthetic oracle. So this
phase builds the mechanisms that do not need the evidence, ships them disabled, and says plainly what is not claimed.

## What was built

| Piece | Switch / preset | What it does |
|---|---|---|
| Affected tests first (`evaluation/affected_tests.py`, `agents/verifier.py`) | `affected_tests_first` / **Q1** | After a repair, run the test files tied to the changed files first (same name, imports, or the changed test itself). A failing subset is returned as a repair signal (`partial=true`); a passing subset is followed by the **full suite**, which is the only thing a verdict rests on. The suite-shrink guard and `best_test_count` ignore partial results. |
| Patch edits (`schemas/loop.py`, `workspace.apply_edits`, `agents/repair.py`) | `patch_edits` / **Q2** | Repair may send exact search/replace edits pinned to the file's sha256 instead of whole files. Missing, ambiguous (>1 match) or overlapping `search` text, or a stale hash, raises `PatchConflict`; the output is rejected and the agent is asked again with the reason (it may then send the whole file). Edits match the *original* text. |
| Changed-line coverage (`evaluation/changed_coverage.py`) | `changed_line_coverage` / **Q3** | Joins the lines that differ between two iterations with coverage.py's per-file executed/missing lines; stored in the test-result details. Python only. **Report-only.** |
| Mutation-style check (`evaluation/mutation.py`) | `test_mutation_check` / **Q4** | In a scratch copy, applies a bounded sample of single changes (flip comparison, swap `+`/`-`, negate boolean, `return None`) to the changed code and re-runs the suite; a mutant the suite does not notice survives. Score and survivors go to the test-result details. Python only; time-boxed; **report-only**. |
| Memory expiry (`agents/repair.py`) | `memory_expiry` / **Q5** | With `MEMORY_TTL_DAYS > 0`, repairs older than that are not offered as hints. |
| Memory opt-out (`tasks.learn_from_task`, migration 0011, UI checkbox) | none (always honoured) | A task created with `learn_from_task=false` is never a source of hints for other tasks, even though the retrieval switch is on. Organization isolation is unchanged. |
| Go adapter (`execution/languages.py` `GO`, `evaluation/go_report.py`, `sandbox/go/`) | language `go` | `go test -json` (parsed from stdout), statement coverage profile, `go vet`, go.mod policy (standard library only; `require`/`replace`/`toolchain` refused), `_test.go` guard, repo map, same-package repair context, failure classes, planner note. Commands are allowlisted narrowly (`go test`, `go vet` only). |
| 10 Go benchmark tasks (`benchmarks/tasks_go`, `validate_go.py`, `--suite go`) | - | Small standard-library functions with reference solutions and >=5 hidden tests each, generated by `tools/generate_go.py`. |
| Held-out split (`benchmarks/heldout.json`, `--heldout` / `--exclude-heldout`) | - | 7 tasks never used for tuning; `check_defaults.py` fails if one is in the regression subset. |
| Presets | **P5** = all five Phase 16 switches on | `check_defaults.py` fails if any Phase 16 switch defaults to on. |

## Decisions
- **Default off, ablate one at a time.** Q1-Q5 turn exactly one switch on, P5 all of them. Until a real run supports a switch,
  `benchmarks/check_defaults.py` forbids turning it on in `LoopConfig`.
- **The full suite always runs before any verdict.** Affected-tests-first can only make a failure appear earlier; it can never
  make something look green.
- **Patch conflicts reject, never merge.** There is no fuzzy matching: an edit applies exactly or not at all.
- **Verification additions are report-only.** Neither coverage of changed lines nor the mutation score changes a verdict or an
  escalation; a threshold would be a new, unmeasured decision rule.
- **Opt-out is not a switch.** A person who says "do not learn from this task" is obeyed regardless of experiment configuration.
- **Go is standard-library only.** The sandbox has no network, so a module could only be used if vendored into the image; the
  approved list is empty on purpose.

## Known limits
- **No real-model result exists for any of this.** Q1-Q5 and P5 have only been exercised on fakes and scripted sandboxes. The
  roadmap's "statistically supported improvement on held-out tasks" is **not** achieved or claimed; Gate 16 only proves the
  mechanisms work, are off by default, and are measurable.
- **The Go adapter and its tasks were written without a Go toolchain and without a Docker daemon on the author's machine.** The
  reference solutions and hidden tests have never been compiled; `validate_go.py` runs only its static checks without `go` (loudly).
  The Go image is unbuilt. Run `python benchmarks/validate_go.py --require-go` and build `backend/sandbox/go/Dockerfile` before
  trusting either. Known risk: `/tmp` is mounted `noexec` in the sandbox, so the image points Go's temp/cache at `/out`; whether
  `/out` allows executing the compiled test binary is unverified.
- **Go has no security scanner** (only `go vet`) and no import-graph awareness beyond the package directory. Java, TypeScript
  frameworks beyond Jest, symbol/dependency-graph retrieval over a whole repository, and dependency-install caching (no network in the
  sandbox, so it is a build-time concern) are not built.
- The Go and held-out tasks are **real-provider only**, like the Phase 8 tasks; the oracle cannot answer them.
- Affected-test selection is a heuristic (names and imports). It can miss tests that reach code through indirection, which costs
  time, not correctness.
- Mutation testing is a bounded sample on Python, with `ast.unparse` rewriting formatting in the scratch copy; equivalent mutants
  are counted as survivors.
- Memory expiry is a retrieval filter: old rows stay in the database (retention is still the organization's `retention_days`).
- Not done: "fix the biggest failure classes from the Phase 14 analysis" - there is no analysis to act on yet.
